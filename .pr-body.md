## Summary

- plugin#80's hook version-resolve fix picked the newest sibling directory via `sort -V | tail -1` without filtering for semver names — safe in a per-version cache layout, but fragile in a marketplace layout (`~/.claude/plugins/marketplaces/{otta,superpowers-marketplace,...}`) where siblings are plugin NAMES, not versions. Found while sweeping repos for the frozen-hook bug: it happened to fall back correctly today only by luck (the wrongly-guessed sibling's `otta-gate.sh` didn't exist).
- `install-git-hooks.sh` now filters candidate sibling dirs to `X.Y.Z/` (semver) before sorting, so a non-version sibling can never be picked.

```acceptance
GIVEN a hook install directory whose siblings are NOT semver-named (e.g. a marketplace layout with other plugin dirs)
WHEN the pre-push hook runs
THEN it resolves to the correct otta plugin's gate script, never an unrelated sibling directory's script

- [x] AC2 `[data-layer]`: Given a genuine per-version cache layout (X.Y.Z sibling dirs), when a newer version appears, then the hook still resolves to it (regression guard for plugin#80's original fix). — same test, earlier assertions
```
