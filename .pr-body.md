## Summary

- Adds deterministic repair policy with a three-attempt default and repeated-failure escalation.
- Persists and verifies terminal repair evidence through the Otta ledger/Pulse transport.
- Adds composable verification labels while preserving existing acceptance-layer tags.

```acceptance
GIVEN an Otta state-changing workflow with failed review feedback
WHEN repair attempts repeat the same blockers or exhaust the configured maximum
THEN the workflow stops safely, records verified evidence, and reports the blockers clearly
```

- [x] [test] Builder/reviewer repair cycles stop after a configurable maximum, defaulting to three.
- [x] [test] The workflow stops and escalates when the same normalized failure signature repeats twice without meaningful progress.
- [x] [test] Acceptance criteria support exactly three initial verification labels: `[test]`, `[review]`, and `[human]`.
- [x] [test] Existing unlabeled acceptance criteria remain backward compatible and receive an explicit default classification.
- [x] [review] Stop and escalation output names the attempt count and repeated blockers in human-readable form.
- [x] [test] Pulse receives compact attempt, stage, failure-signature, and outcome evidence when configured.
- [x] [test] Read-only investigations remain outside the mandatory issue/PR workflow.
