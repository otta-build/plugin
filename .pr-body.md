## Summary

- Adds a `lint` job to CI running shellcheck over `scripts/*.sh` and `hooks/*.sh`: a blocking gate at error severity, plus a non-blocking report for warning/info/style.
- The tree is already clean at error severity, so this gates going forward without requiring a single code fix.
- Adds `tests/shellcheck-gate.test.sh`, which guards both that the gate stays wired and that the tree stays clean — the two things that can rot independently.

```acceptance
GIVEN a shell script in scripts/ or hooks/ containing an error-severity shellcheck defect
WHEN  CI runs on the pull request
THEN  the lint job fails, while warning/info/style findings only print
```

- [x] [data-layer] CI runs shellcheck over `scripts/*.sh` and `hooks/*.sh`.
- [x] [data-layer] The job fails when shellcheck reports any `error`-severity finding.
- [x] [data-layer] `warning`/`info` findings appear in the job log but do not fail the build.

## Acceptance Evidence

- [x] AC1: the `lint` job runs both invocations against `scripts/*.sh hooks/*.sh`; case 4 of the test asserts both directories appear.
- [x] AC2: the error-severity run has no `|| true`. Case 2 of the test asserts that specifically — a gate that cannot fail is not a gate, and that is the easiest thing to silently regress.
- [x] AC3: the report step is a separate `--severity=style` run terminated with `|| true`, so lower severities print without blocking.
- [x] AC4: `otta-learning-policy.py` is excluded by the `*.sh` glob, not by a directive. Case 5 asserts no `shellcheck disable=all` was added to it. This is why #176 had to land first — the file was `.sh` until then, and shellcheck cannot parse a Python polyglot.
