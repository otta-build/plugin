## Summary

- pre-push-guard.sh now resolves the repo actually targeted by a `git push` command (`-C <path>`, cumulative `-C`, `cd <path> &&` compound forms, and subshell-wrapped `(cd <path> && git push)`) and gates that repo's `.pr-body.md`, instead of always gating the session cwd's repo.
- Ambiguous or unresolvable targets (e.g. multiple pushes to different repos in one compound command) fail closed to the session repo, so the gated repo can never fail open.
- Push detection is metachar-safe: `push` followed by `)`, `&`, `|`, `>`, etc. (e.g. `(git push)`, `git push&`) is still detected, closing a fail-open gap where those forms silently skipped the gate entirely.

```acceptance
GIVEN a session cwd inside a gated repo with a stale/failing .pr-body.md
WHEN  the agent runs `git -C <other-repo> push` or `cd <other-repo> && git push`
THEN  the gate does not run and the push is not blocked by the session repo's .pr-body.md
```

- [x] pre-push-guard.sh resolves the repository actually targeted by the push command (honor `git -C <path>`, `-C` before subcommand, and cwd-relative pushes) and runs the gate only when that repo is the Otta-gated repo.
- [x] A push targeting a different repo from within a gated-repo session cwd is NOT gated (regression test with a temp secondary repo).
- [x] A push targeting the gated repo still gates exactly as today (existing tests pass).
- [x] Stale-post-merge `.pr-body.md` (Fixes #N where N closed) in the session repo no longer blocks unrelated pushes (covered by the scoping fix; test asserts).
