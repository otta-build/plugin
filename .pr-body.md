## Summary

- `pre-push-guard.sh` now collapses shell backslash-newline line continuations (`git \` + newline + `push`, including the CRLF variant `git \` + CR + LF + `push`) into a single line before splitting the command into segments, so continuation-form pushes are detected and gated instead of silently passing (`push_segments_seen=0` → exit 0).
- The hook header now documents the detection-vs-resolution fail philosophy: resolution failures (which repo?) fail closed onto the session repo, while detection failures (is this a push at all?) currently fail open, so the parser errs toward recognizing more shell forms as pushes.

```acceptance
GIVEN an agent runs `git \` + newline (or CRLF) + `push origin main` (or `git push \` + newline + `--force`) against a gated repo
WHEN  pre-push-guard.sh processes the command
THEN  the continuation is collapsed before segment parsing, the push is detected, and the gate runs/blocks exactly as a single-line `git push` would
```

- [x] Backslash-newline line continuations are collapsed before segment parsing, so `git \<newline>push` (and `git push \<newline>--force`) is detected and gated on the gated repo. Regression test (TDD: fails on current main first).
- [x] Detection-failure philosophy documented in the hook header: what fails closed (resolution) vs what would fail open (undetected push) and why the parser errs toward detection.
- [x] All existing pre-push-guard tests (7-check target-repo + nested) still pass.
- [x] CRLF-style continuation (`git \<CR><LF>push`) is also collapsed and detected — not just plain LF.

## Out of scope
- Other undetected shell forms of `push` beyond backslash-newline continuations (e.g. command substitution, aliases) — not part of this issue's scope.
