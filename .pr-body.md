## Summary

- Install one idempotent natural-language routing policy for Claude Code and Codex while preserving every explicit Otta command as the deterministic API.
- Add backward-compatible named staging/production deployment environments and thread the resolved environment through delivery.
- Add fail-closed latest-wins inclusion, GitHub Workflow safety readiness, and explicit deployment status outcomes without a broker or provider adapter.

Prior slice: issue #148 / PR #150 shipped the v1.4.3 design contract; Pulse reports no reopened issue, revert, or failed verdict for that idea.

```acceptance
GIVEN an Otta-enabled GitHub repository used from Claude Code or Codex
WHEN developers work or release concurrently using natural or explicit intent
THEN Otta routes the canonical lifecycle and deploys only a proven eligible SHA through the configured repository workflow
```

- [x] Setup installs an idempotent Otta intent policy into Claude Code and Codex repository context that covers setup, start, dev, build, fix, ship, status, schedule, remember, and pulse-doctor; explicit invocations win and read-only/status intent never causes a write.
- [x] The deployment configuration supports optional named environments with an explicit default while legacy flat v1.4.1 deploy blocks continue to parse and behave unchanged.
- [x] Ship/deploy selects the requested or configured environment, binds production approval to the exact current PR head, and keeps repository-owned GitHub workflows as the sole ordinary provider mutation boundary.
- [x] Concurrent releases use latest-eligible-wins semantics: an older request becomes superseded or included only when a same-environment, policy-eligible descendant is proven; divergent, unapproved, ambiguous, and rollback targets fail closed.
- [x] Setup/readiness validates the workflow dispatch, exact-SHA marker, non-cancelling per-environment concurrency, verification contract, and competing production triggers, and warns when repository-local concurrency cannot protect a shared constrained host.
- [x] Focused tests cover Claude/Codex routing parity, staging plus production, production-only, no-runtime, legacy flat config, same-SHA duplicates, 5-10 concurrent requests, cancelled pending runs, unapproved newer commits, divergence, restart/recovery, and stale or malformed runtime evidence.

- A central broker, distributed lock database, or provider-specific deployment adapter.
- Non-GitHub source-control providers.
