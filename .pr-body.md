## Summary

- Specify natural-language routing across the complete Otta command surface.
- Define optional staging/production profiles and latest-wins releases without a broker.
- Preserve one canonical lifecycle across Claude Code and Codex with GitHub enforcement.

```acceptance
GIVEN an Otta-enabled GitHub repository used through Claude Code or Codex
WHEN a developer expresses setup, development, status, or release intent naturally
THEN Otta routes through the canonical command lifecycle and GitHub enforces verifiable delivery evidence
```

- [x] The design specifies natural-language routing and fallback behavior for setup, start, dev, build, fix, ship, status, schedule, remember, and pulse-doctor in Claude Code and Codex.
- [x] The design keeps one harness-neutral core with thin Claude/Codex adapters and cross-harness resumption from GitHub evidence.
- [x] The design supports projects with staging plus production, production only, and no runtime deployment, while preserving the v1.4.1 flat deploy contract.
- [x] The design specifies latest-wins handling for 5-10 concurrent release attempts, including superseded/included outcomes and host-load protection.
- [x] The design remains provider-neutral through repository-owned GitHub workflows and covers staging and direct-production policies.
- [x] The design identifies server-side enforcement, verification, rollout tests, migration, recovery, and explicit non-goals that avoid a central broker or provider-specific Otta implementation.

- LeadCognition repository or deployment changes.
- A central release broker, distributed lock database, or provider-specific Otta adapters.
