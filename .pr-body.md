## Summary

- Add independent per-run consultation and capture policy resolution with repo, environment, and explicit run-override precedence.
- Consult active Otta Engine or manual `otta:remember` `LEARNINGS.md` rules through one shared workflow contract and emit metadata-only, repository-locally ignored receipts for every attempt.
- Route gate, reviewer, and QA capture through the resolved policy while keeping local ledger/Pulse integrations optional.

```acceptance
GIVEN a repository with independent LEARN consultation and capture defaults
WHEN an interactive dev, autonomous build, or tiny fix run resolves its learning policy
THEN active rules and verdict capture follow their independent decisions and leave inspectable metadata-only receipts
```

- [ ] AC1: A run resolves independent consult and capture decisions from repo defaults with explicit per-run overrides; disabling one does not disable the other.
- [ ] AC2: Before build, Otta deterministically reads active non-expired LEARNINGS.md rules when consultation is enabled and supplies the result to the workflow; disabled or unavailable consultation fails open with an explicit reason.
- [ ] AC3: Every consultation attempt emits an inspectable local receipt containing policy decisions, rule identifiers or counts, provenance, and a consulted or skipped reason without copying raw session or secret content.
- [ ] AC4: Gate, reviewer, and QA verdict capture consistently honor the resolved capture decision and record an explicit skipped reason when capture is disabled.
- [ ] AC5: The interactive dev, autonomous build, and tiny fix paths document and invoke the same policy contract without making Mem0, ChatGPT memory, or an owner Brain a product dependency.
- [ ] AC6: Regression tests first cover independent controls, config and override precedence, active and expired rules, receipts, capture opt-out, and safe malformed or missing config behavior.

## Out of scope
- Background LLM consolidation or direct rule promotion.
- Personal Brain, Mem0, or ChatGPT memory synchronization.
- Cockpit UI controls or changes to Otta Engine rule induction.
