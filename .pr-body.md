## Summary

- Add a native Task/`/goal` protocol to `/otta:start` and `/otta:dev` (TaskCreate/TaskUpdate per stage, markdown fallback), and fix invalid `#`-containing agent names that would have broken `SendMessage` resume.
- `/otta:dev`'s Claude Code fix loop now resumes the existing named builder via `SendMessage({to: ...})` instead of respawning; Codex `send_message` path untouched.
- Harden the 4 pipeline agents' frontmatter with `disallowed-tools: Task, Agent` (explicit spawn restriction) and a stage-appropriate `effort`.
- Document the 4 Pulse OTel correlation attributes (`workflow.run_id`, `workflow.name`, `agent_id`, `agent_type`) in the telemetry setup surface.
- Add an opt-in `experimental.monitors` manifest entry that watches gate/CI after `/otta:ship`; `otta-deploy-verify.sh` polling remains the fallback, untouched.
- Audit `hooks/hooks.json` for the 2.1.207 shell-injection pattern (clean) and add a regression guard; the exec `args` migration is deferred to #155 (Codex reads the same file — see rescoped (c2) below).

Codex) lacking these primitives

- [x] (a) `/otta:start` and `/otta:dev` define a first-class native task protocol: on start, create one task per pipeline stage (build, spec-review, verify, ship) via TaskCreate and update status on stage transitions via TaskUpdate; instruct setting the session goal from the issue's acceptance criteria via `/goal` where available. Markdown checklist remains the documented fallback when task tools are unavailable. Verified by a test asserting the protocol text (TaskCreate, TaskUpdate, goal) exists in both command files.
- [x] (b) `/otta:dev` fix-loop for Claude Code resumes the existing named builder via `SendMessage({to: <builder name>})` with reviewer feedback instead of spawning a fresh builder; Codex `send_message` path unchanged. Verified by a test asserting SendMessage resume instruction in dev.md.
- [x] (c1) Pipeline agents declare spawn restrictions so review/verify/ship stages cannot spawn other pipeline agents (`Task(agent_type)` syntax or equivalent `disallowed-tools`), and each of the 4 agents declares an explicit `effort` appropriate to its stage. Verified by a test asserting the frontmatter fields in all 4 agent files.
- [x] (c2) `hooks/hooks.json` audited for the 2.1.207 shell-injection pattern (`${user_config.*}` in shell-form commands): none present — audit result recorded here. Migration to exec `args` array form is deferred to #155 because `.codex-plugin/plugin.json` executes the same shell strings via `bash -c` (`tests/codex-plugin-parity.test.sh`) and the two forms are mutually exclusive. Verified by `tests/hooks-shell-injection-guard.test.sh` asserting no `${user_config.*}` appears in any hooks.json command.
- [x] (d) OTel correlation attributes are wired for Pulse: setup/telemetry docs and the telemetry step emit or document `workflow.run_id`, `workflow.name`, `agent_id`, `agent_type` attribute usage so Pulse can join runs to stages; `.otta.yml`/setup guidance updated. Verified by a test asserting the attrs appear in the setup/telemetry surface.
- [x] (e) Plugin declares an opt-in `monitors` manifest entry (or documented equivalent) that watches gate/CI status after ship, replacing hand-rolled polling in the deploy-verify path where the Monitor tool is available; polling remains the fallback. Verified by a test asserting the manifest entry or gated instruction exists.
- [x] All features degrade gracefully: no behavior change for harnesses lacking these primitives (explicit availability checks or instruction-level gating).
- [x] Ships as a single release: PR merges to main with a `feat:` title so `auto-release.yml` bumps 1.5.0 → v1.6.0 and generates the CHANGELOG entry covering (a)–(e) (release automation is authoritative; hand-bumps break `marketplace-version-sync.test.sh`).

## Out of scope
- Converting `hooks/hooks.json` to exec `args` form — deferred to #155; needs a Codex-safe design (e.g. separate hook manifests per harness) since Codex executes the same shell-string `command` field via `bash -c` and the CC exec `args` form is mutually exclusive with it.
- Manual `.claude-plugin/plugin.json` / `CHANGELOG.md` version bump — `auto-release.yml` computes the next semver from conventional-commit messages on merge to `main` (feat → minor: 1.5.0 → 1.6.0) and syncs `marketplace.json` + `.codex-plugin/plugin.json` in the same commit; hand-bumping here would desync those 3 manifests and fight the automation (`tests/marketplace-version-sync.test.sh`).
