## Notes for the reviewer

Two design decisions worth checking:

1. **The guard needs an opt-in marker.** This is a global `PreToolUse` hook, so failing closed on every branch-ahead push would block feature-branch pushes in every unrelated repo on the machine. It gates on `.otta.yml`, the same marker `otta-deploy-readiness.sh:93` already uses. Test case 2 exists specifically to pin that false-positive boundary.

2. **A wrapper, not a rename.** 11 call sites in `agents/`, `commands/`, `workflows/` and `scripts/` invoke `otta-learning-policy.sh` by name, plus 2 tests assert that literal path. A full rename is a 13-file diff; the wrapper is 2 files and keeps the public interface identical.

**The new check caught a real defect in this very PR body.** The first draft quoted a test failure message verbatim, and that message contains a GitHub closing keyword pointing at issue 65. GitHub scans the whole body for those keywords, so merging would have auto-closed an unrelated issue. The gate flagged it because it reads the *first* such reference anywhere in the body — deliberately matching GitHub's own behaviour rather than restricting itself to line starts, which would have let the hazard through.

`skills/ac-layers/` is deliberately unprefixed: `tests/codex-plugin-parity.test.sh` requires `skills/otta-*` directories to mirror `commands/*.md` exactly, and this is a reference doc with no command. It follows the existing `learn-from-pulse` / `shipping-loop` precedent.
