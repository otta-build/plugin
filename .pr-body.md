### c2 deviation (open question for the team lead)

`hooks/hooks.json` is read by **both** the Claude Code and Codex plugin manifests (`codex-plugin-parity.test.sh` asserts `.codex-plugin/plugin.json` points at the same file and literally `bash -c`'s the shell-string `command` field to simulate Codex's dual-runtime execution). Verified against current Claude Code hook schema: the exec `args` form and the shell-string `command` form are **mutually exclusive** on a single hook object — when `args` is present, `command` must be a bare executable name (e.g. `"command": "bash", "args": [...]`), which destroys the self-contained shell string Codex's `bash -c "$command"` depends on. Converting hooks.json to args-only form would break the Codex path, violating the explicit "never break Codex paths" directive. Left `hooks/hooks.json` unchanged; added `tests/agent-frontmatter-hardening.test.sh` etc. instead of a hooks-args test. **Question:** is a Codex-specific hooks file split (out of scope for this issue) an acceptable follow-up, or should (c2) be dropped/rescoped?

## Out of scope
- Converting `hooks/hooks.json` to exec `args` form (see "c2 deviation" above) — needs a Codex-safe design (e.g. separate hook manifests per harness), which is a bigger structural change than this issue.
