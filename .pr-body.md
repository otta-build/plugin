## Summary

- `otta-deploy-verify.sh` now performs one live `gh pr view --repo <canonical>` read before any merge, prints the resolved repo/PR URL/head SHA/base SHA, and fails closed if the PR's own URL doesn't resolve back to the canonical repo (derived fresh from `git remote origin` on every invocation).
- The legacy (non-`github-workflow`) merge path gained the pre-merge state check it was missing entirely: it no longer calls `gh pr merge` blind, so an already-merged/foreign PR #`<n>` can no longer be reported as a false "deploy: merged PR #`<n>`" — the exact failure mode in the issue.
- The `github-workflow` executor's two existing PR reads (initial resolve + pre-merge refresh) now include `url`/`baseRefName`/`baseRefOid` and go through the same identity check.

```acceptance
GIVEN a repo whose `git remote origin` resolves to repo B, and PR #17 in repo A (a different repo) is already merged
WHEN  `otta-deploy-verify.sh 17` runs with `auto: merge-on-green`
THEN  it merges repo B's own open PR #17, never reports repo A's merge as its own, and never calls `gh pr merge` on an already-merged PR
```

- [x] AC1: Deploy state keys include canonical `owner/repo` and PR number. — `gh_repo` is derived from `git remote origin` and threaded via `--repo`/`-R` into every `gh` call and into the ledger (`${repo//\//-}.jsonl`) and `workflow_deploy_key` (repo is its first argument); no PR-number-only key exists anywhere in the script.
- [x] AC2: A changed repository invalidates or ignores any prior state for the same PR number. — `gh_repo` is re-derived from `git remote origin` on every invocation (the script keeps no cross-invocation state); test: "AC4 repo B ... carries no repo-A residue".
- [x] AC3: Before merge, the script prints and verifies canonical repo, PR URL, head SHA, and base SHA from the same live query. — new `_print_and_verify_pr_identity` (scripts/otta-deploy-verify.sh), wired into the legacy pre-merge path and both `github-workflow` PR reads.
- [x] AC4: Regression test covers two repositories with PR #17 in different states. — tests/otta-deploy-verify.test.sh section 11d ("AC4 repo A ...", "AC4 repo B ...").
- [x] AC5: The script fails closed when stored repo identity and live repo identity differ. — `_print_and_verify_pr_identity` returns 1 (no mutation) when the PR URL's owner/repo doesn't match canonical `gh_repo`; the legacy path also fails closed when the live PR state isn't `OPEN`.

## Out of scope
- The underlying detection gap in how `gh_repo` itself could historically have been resolved wrong (e.g. `gh` default-repo confusion) — this fix makes the script self-verifying regardless of how `gh_repo` was derived, rather than auditing every possible cause of a bad `gh_repo`.
