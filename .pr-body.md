# feat(setup): offer sandbox.credentials hardening (idea #6)

Adds an **optional** step 7 to `/otta:setup` that offers to write `.claude/settings.json` with `sandbox.enabled` + `sandbox.credentials` deny-lists, so the pipeline's Bash commands can't read credential files (`~/.aws`, `~/.ssh`, `~/.config/gcloud`) or token env vars (`GITHUB_TOKEN`, `AWS_*`, `NPM_TOKEN`). Completes the governance story: Otta gates AI-written code AND stops it reading secrets.

Opt-in only — sandbox mode also isolates filesystem + network and has platform requirements (macOS/Linux-WSL2, not native Windows; Linux needs bubblewrap+socat), so the step states the trade-offs and only writes the file if the developer says yes (merge, never clobber).

Contract verified against CC docs (settings.md + sandboxing.md, v2.1.187+): exact `sandbox.credentials` shape ({files:[{path,mode}], envVars:[{name,mode}]}), the `sandbox.enabled` precondition, subagent scope, and platform limits.
