## Summary

- `otta-worktree.sh` no longer appends `.otta/session.json` to the target repo's **tracked** `.gitignore`. Every pipeline run used to start with a dirty working tree in a file unrelated to the issue being worked on.
- The ignore now goes to `$GIT_COMMON_DIR/info/exclude` — repo-local, never tracked, shared across all worktrees of a repo, so it is naturally idempotent.
- Same mechanism `otta-learning-policy.py` already uses for `/.otta/run/` in `ensure_local_run_ignore()`, so this makes the two consistent rather than inventing anything.

```acceptance
GIVEN a repo whose .gitignore is tracked
WHEN  otta-worktree.sh creates a worktree
THEN  `git status --porcelain` is empty, and `.otta/session.json` is still ignored
```

- [x] [data-layer] Creating a worktree leaves the target repo's tracked files unmodified — `git status --porcelain` shows no `.gitignore` entry.
- [x] [data-layer] `.otta/session.json` is still effectively ignored and cannot be accidentally committed.
- [x] [data-layer] Behaviour is idempotent across repeated worktree creation.
- [x] [data-layer] Repos that already carry the `.gitignore` line are not broken and do not get a duplicate.
- [x] [data-layer] Regression tests cover the clean-tree and idempotency criteria, and fail before the fix.
- [x] [data-layer] Full `tests/*.test.sh` suite passes.

## Why it mattered

The intent was right — `.otta/session.json` is token-adjacent and must never be committed. The mechanism wasn't. Because `.gitignore` is normally tracked, the append showed up as a real modification on every single run. Reviewers correctly stripped it as scope creep (reverted in otta-build/pulse#138), so it never landed, and reappeared on the next run.

That is worse than it sounds: it trains everyone to see a dirty tree at the start of a pipeline run as normal, which is exactly the state in which a genuine unintended change goes unnoticed.

This was observed first-hand during the #176 work — the very first worktree created came up with `?? .gitignore` containing only that line.

## Note

The helper returns 0 on every failure path — unreadable `info/exclude`, read-only `.git`, `rev-parse` failing outside a repo. An ignore that cannot be written is not a reason to fail worktree creation, and the previous code was equally best-effort. The consequence is unchanged: `.otta/session.json` is untracked either way, so nothing can be committed by accident just because the ignore is missing.

Closes otta-build/dev#83, which tracks this from the consuming side.
