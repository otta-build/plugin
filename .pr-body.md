## Summary

- Poll and verify Pulse repository access plus `checks:write` after setup, and use that server truth in readiness.
- Reuse `.otta/pulse.env` for hosted Claude/Codex telemetry while preserving authenticated self-hosted derivation.
- Mark Pulse Doctor as operator-only and align the setup documentation with that boundary.

```acceptance
GIVEN a repo selected hosted Pulse setup and completed browser consent
WHEN setup and readiness query Pulse with the repo-scoped token
THEN only verified repository access plus checks:write is reported connected, telemetry reuses that token, and App credentials remain operator-only
```

- [x] Setup polls the customer-safe Pulse installation-status endpoint after browser consent and fails clearly for missing access or stale `checks:write` approval.
- [x] Readiness verifies hosted installation status when Pulse is configured; file existence alone is not reported as connected.
- [x] Hosted Claude and Codex telemetry setup reuse the repo-scoped token already written to `.otta/pulse.env`; they do not call the admin `/token` endpoint unauthenticated.
- [x] Pulse Doctor is explicitly operator-only and directs hosted customers to setup/status instead of requesting App private credentials.
- [x] Self-hosted behavior remains supported and documents the operator credential boundary.
- [x] Regression tests cover installed, missing, permission-stale, unavailable/fail-open policy, token reuse, and operator-doctor messaging.
- [x] Setup documentation and readiness output match the implemented behavior.
