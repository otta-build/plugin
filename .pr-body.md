## The failure mode, demonstrated

Two directories matching `*-1/.git`, run against the old construct:

```
$ [ -e "$D"/*"-1/.git" ] && echo "asserted OK" || echo "assertion FAILED"
bash: line 1: [: /tmp/.../decoy-1/.git: binary operator expected
assertion FAILED
```

One directory, same construct:

```
$ [ -e "$D"/*"-1/.git" ] && echo "asserted OK" || echo "assertion FAILED"
asserted OK
```

So the behaviour was:

| matches | old construct | new |
|---|---|---|
| 0 | correct by accident — glob stays literal, `-e` false, `fail` fires | correct |
| 1 | correct — **the only case ever hit, which is why this survived** | correct |
| 2+ | **`[` errors and returns false → an existing worktree reported missing** | correct, count reported |

That the 2+ branch reports a *false negative* rather than erroring out loudly is what makes it worth fixing: it would have surfaced as "worktree for issue 1 missing" — a plausible-looking failure pointing at entirely the wrong thing.

This is also the one test where 2+ is plausible: it fires six concurrent `otta-worktree.sh` calls against a shared `.git`.
