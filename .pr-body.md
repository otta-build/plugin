## Summary

- `hooks/pre-push-guard.sh` used to check `.pr-body.md` (and invoke the gate) relative to the current working directory instead of the git repo's toplevel, so a nested/parent repo's stale `.pr-body.md` could leak into the wrong repo's push decision.
- Guard now resolves `git rev-parse --show-toplevel` and reads/passes `$TOPLEVEL/.pr-body.md` explicitly to `otta-gate.sh`, so the check and gate always operate on the pushed repo's own file.

```acceptance
GIVEN a pushed git repo whose CWD may not be its toplevel (e.g. a nested or parent repo also has a .pr-body.md)
WHEN  pre-push-guard.sh runs on a `git push` command
THEN  the guard only reads/gates the .pr-body.md at the pushed repo's own git toplevel, ignoring any other repo's file
```

- [ ] AC1: pre-push guard resolves the pushed repo's toplevel and reads only its own .pr-body.md
- [ ] AC2: test: nested repo with stale .pr-body.md does not block the parent repo's push
