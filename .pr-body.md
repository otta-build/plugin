## Summary

- Adds `/otta:batch <issue> <issue> ...` — runs the existing `build → spec-review → verify → ship` pipeline across many issues **concurrently**, one worktree-isolated lane and one PR per issue, by riding the Workflow tool's native `parallel()`. Otta owns the gate on each lane; no scheduler is built.
- New `workflows/otta-batch.mjs` fans out to the unchanged `otta-build.mjs` per issue (invoked by `scriptPath`, one-level nest) and summarizes verdicts; pure helpers `normalizeIssues`/`summarizeBatch` are unit-tested.
- New portable `mkdir`-based lock (`scripts/otta-lock.sh`; `flock` is absent on macOS) guards the two resources concurrent lanes share: `git worktree add` on the shared `.git`, and the per-repo ledger append. The lock self-heals a stale dir left by a killed lane.

```acceptance
GIVEN several open issues and `/otta:batch 101 102 103`
WHEN  the batch workflow fans out one otta-build lane per issue via parallel()
THEN  each lane runs the full gated pipeline in its own worktree and opens its own PR,
      a failed lane is reported blocked without aborting the batch, and concurrent
      worktree-creation and ledger-append are race-free (mkdir lock, self-healing).
```

- [ ] `/otta:batch 101 102 103` fans out one `otta-build` lane per issue via `parallel()`, each in its own per-issue worktree (proven: nested `workflow({scriptPath})` runs lanes concurrently).
- [ ] A failed/thrown lane is reported `blocked` and does NOT abort the batch (`summarizeBatch` maps a `null` lane → `{status:'blocked', reason:'lane-error-or-null'}`); verified by `tests/otta-batch-helpers.test.sh`.
- [ ] Concurrent `git worktree add` across lanes never races with `fatal: could not lock` — guarded by a portable `mkdir` lock (`flock` is absent on macOS); verified by `tests/otta-worktree-concurrent.test.sh`.
- [ ] Concurrent ledger appends across lanes yield N intact JSON lines (no interleave past PIPE_BUF) — same lock; verified by `tests/ledger-append-concurrent.test.sh`.
- [ ] A lock left by a killed lane self-heals (stolen after `OTTA_LOCK_STALE_SECS`, default 300s) instead of wedging the repo; verified by `tests/otta-lock.test.sh`.
- [ ] `/otta:batch` resolves the plugin root with the standard `OTTA_PLUGIN_ROOT/PLUGIN_ROOT/CLAUDE_PLUGIN_ROOT` fallback (matches every other command).

## Out of scope
- Label / auto issue selection (`--label otta:ready`) — fast-follow once the parallel core is proven.
- Remote executor (Hetzner headless Jean) behind the same executor seam.
- Cross-issue dependency DAG.
- Per-issue CI/CD speed (caching, runners, test splitting) — a separate track; parallelism overlaps CI waits, it does not shorten a single run.

## Verification
- unit: `bash tests/otta-lock.test.sh` (4 checks incl. mutual-exclusion under 20-way contention + stale-lock steal), `bash tests/otta-worktree-concurrent.test.sh` (6 concurrent `git worktree add`, no lock race), `bash tests/ledger-append-concurrent.test.sh` (16 concurrent 6KB appends, N intact JSON lines), `bash tests/otta-batch-helpers.test.sh` (`normalizeIssues`/`summarizeBatch`, incl. null-lane → blocked). Full suite `FAILURES: 0`.
- e2e: parallel fan-out proven via a throwaway Workflow run — nested `workflow({scriptPath})` under `parallel()` returned two concurrent lanes (`LANE-A-DONE`, `LANE-B-DONE`), 0 errors. Live two-issue batch smoke deferred to reviewer/QA.
- preview: n/a — CLI/plugin change, no preview env.
