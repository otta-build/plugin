# feat(hooks): SubagentStop gate — run the Otta gate at the build-stage boundary

Top-ranked idea from the CC release-notes brainstorm. The gate previously fired only at `git push` (PreToolUse). This adds a **`SubagentStop`** hook so the gate also runs when the `otta:builder` subagent finishes — a build stage can no longer report "done" past a failing gate. On failure it exits 2 (blocks the stop) and writes the failing-check detail to stderr, which Claude Code feeds back to the subagent so it keeps fixing.

SubagentStop contract verified against current CC docs: matcher = agent type, stdin carries `agent_type`/`cwd`, exit 2 blocks + surfaces stderr to the subagent, `${CLAUDE_PLUGIN_ROOT}` available, 8-block loop cap.

## Design
- **Scoped to the builder stage only** — reviewer is read-only, qa already runs the gate, devops opens the PR after the gate passed. Self-filters on `*builder` (matches `otta:builder` or a bare `builder`); matcher `*` for robustness to the exact registered type string.
- **Guards so it never fires wrongly:** non-builder type → skip; no `.pr-body.md` (repo not in the loop) → skip; `OTTA_SKIP_GATE=1` → bypass. Runs in the subagent's `cwd` (the worktree).
- Reuses the existing `otta-gate.sh` (which also captures each run to the LEARN ledger — so build-stage checks now accrue training data too).
