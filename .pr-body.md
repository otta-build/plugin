## Summary

- Adds `/otta:status <issue-or-pr>` — a read-only pipeline stage tracker (Idea → Build → Gate → CI → Release/Deploy) for Claude Code.
- New `scripts/otta-status.sh`: a pure JSON-in/checklist-out renderer (no network I/O), so it's unit-testable without stubbing `gh`/`curl`. The command doc instructs the agent to gather `gh api`/`gh pr checks` + optional Pulse `gate_verdict` data, then pipe a small JSON object into the script.

```acceptance
GIVEN an issue or PR number
WHEN  the developer runs `/otta:status <N>`
THEN  a terminal checklist renders Idea/Build/Gate/CI/Release stages with ✓/✗/○ markers, using gh check-run data and (if configured) Pulse gate_verdict, without writing/merging/pushing anything

- [x] New `commands/status.md` slash command added, following the existing command doc pattern (see `commands/dev.md`, `commands/ship.md`).
- [x] Fetches PR/issue state and check-run status via `gh api` / `gh pr checks`.
- [x] Fetches the Pulse `gate_verdict` for the issue's linked idea/session when Pulse is configured; no-ops gracefully (prints "Pulse not configured" style message, does not error) when it isn't — matching the existing opt-in pattern used elsewhere in the plugin (e.g. deploy-verify, telemetry).
- [x] Renders a terminal checklist showing stage progression (Idea → Build → Gate → CI → Release/Deploy) with pass/fail/pending markers per stage.
- [x] Test coverage added per the `tdd-regression` skill (smallest failing test before implementation), following the existing `tests/*.test.sh` pattern in this repo.

## Out of scope
- Writing/merging/deploying anything — `/otta:status` is strictly read-only, unlike `/otta:ship`'s deploy-verify stage.
- A dedicated Pulse `gate_verdict` HTTP endpoint — reuses the existing `/idea?ref=` endpoint (already returns `verdicts` pass/fail counts) rather than inventing a new one, for consistency with the `learn-from-pulse` skill's integration.

## Verification

- e2e: n/a — command is a prompt doc driving `gh`/`curl` at runtime; not scriptable without live GitHub/Pulse state. Manually dry-run the doc's steps against a real PR before merge if reviewer wants extra confidence.
- preview: n/a — no preview env for a CLI slash command.
```
