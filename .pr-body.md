## Summary

- Define one shared, adaptive progress protocol for Otta delivery commands.
- Project progress through Claude Code's native Task/Workflow UI and Codex's native plan UI without duplicating routine narration.
- Make blocked and resumed runs reconstruct their projection from durable Otta status evidence.

```acceptance
GIVEN Otta delivery is invoked in Claude Code or Codex
WHEN it enters, transitions, blocks, resumes, or completes delivery stages
THEN it uses the harness-native progress surface, emits only attention-worthy transcript events, and reconstructs state from durable evidence
```

- [ ] [test] A shared progress protocol defines deterministic profiles: no delivery plan for read-only work, Build/Gate/PR for `otta-fix`, the standard gated pipeline for `otta-dev` and `otta-build`, and Deploy/Verify only when deployment policy requires them.
- [ ] [test] Claude Code preserves native Task/Workflow progress and suppresses redundant transcript narration.
- [ ] [test] Codex creates one native plan projection, updates it only at meaningful stage transitions, and suppresses redundant transcript narration.
- [ ] [test] Both harnesses surface compact attention events for decisions, failures, material risk changes, and completion.
- [ ] [test] Resumed workflows reconstruct current progress from durable Otta ledger/status evidence rather than assuming a fresh run.
- [ ] [test] `/otta:status` and `$otta-status` remain the detailed evidence surfaces; native progress UI is documented as a projection, not the source of truth.
- [ ] [docs] README demonstrates normal, blocked, resumed, and completion states for both Claude Code and Codex.
- [ ] [release] Focused contracts, full plugin tests, Claude Code smoke, and Codex smoke pass before publishing the next plugin version.

## Out of scope
- Changes to the Claude Code or Codex client/TUI implementations.
- Changes to Otta gate semantics, lifecycle policy, or deployment authorization.
