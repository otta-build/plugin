## Summary

- add an additive GitHub workflow deployment executor to the v2 Otta contract
- bind human production approval by exact equality to the immutable PR head, then merge/dispatch at most once
- correlate a dispatched run by workflow/ref snapshot, actor, timestamp, and an exact SHA marker, then require terminal and live health proof
- preserve repository-local Pulse configuration and require the target workflow to self-dedupe the same SHA across machines
- expose an optional exact SHA marker in the existing non-mutating CI workflow for safe remote controller dogfood

```acceptance
GIVEN a repository with an audited workflow_dispatch deployment workflow
WHEN Otta receives commit-bound approval and runs the deploy controller
THEN exactly one workflow run is correlated, terminal success is required, and the live health SHA must match before Otta reports verification
```

- [x] AC1: the v2 `.otta.yml` contract can configure a GitHub workflow deployment executor, workflow file/name, SHA input, provider verification, and health endpoint without dropping existing provider/verify fields.
- [x] AC2: a pure, tested decision layer distinguishes human merge approval from deployment execution and permits post-merge dispatch without auto-merging an open PR.
- [x] AC3: the controller dispatches the configured GitHub workflow exactly once for the PR merge SHA, records/reuses an idempotency key for local retries, and documents target-workflow same-SHA self-deduplication as the cross-machine boundary.
- [x] AC4: the controller polls the dispatched workflow to a terminal result, fails loudly on timeout/failure, and never reports shipped from a successful dispatch alone.
- [x] AC5: after workflow success, the controller verifies the configured live health SHA matches the merge SHA and reports the exact mismatch or unreachable endpoint.
- [x] AC6: legacy human-approve, merge-on-green, merge-and-deploy, and provider-only verification contracts remain backward compatible unless the new workflow executor is configured.
- [x] AC7: tests prove red-to-green behavior for generated v2 contract preservation, human-approved post-merge dispatch, exactly-once retry, workflow failure/timeout, and stale live SHA.
- [x] AC8: docs describe the Otta control-plane flow and explicitly require the target repository to keep one deployment mutation authority plus a documented manual recovery/rollback path.

## Out of scope

- direct Coolify or other infrastructure-provider mutation from Otta
- repository-specific deployment, migration, or rollback implementation
- autonomous production approval
