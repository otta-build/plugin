## Summary

- `install-merge-ours.sh` now self-skips when `.pr-body.md` is gitignored. The driver only protects a *tracked* body; in the untracked model it is dead config that dirties `.gitattributes` on every seed.
- The skip signal is **gitignored**, not "untracked" or "absent" — at `/otta:setup` time the body normally doesn't exist yet, and `setup.md` documents the driver as always installed. Only an explicit `.gitignore` entry counts as opting out.
- Both supported models keep working. This PR does not migrate the plugin to the untracked model — see below.

```acceptance
GIVEN a repo whose .gitignore contains .pr-body.md
WHEN  seed-pr-body.sh runs and calls install-merge-ours.sh
THEN  .gitattributes is left byte-identical and the skip is reported on stdout
```

- [x] [data-layer] `seed-pr-body.sh` does not modify `.gitattributes` in a repo where `.pr-body.md` is untracked or gitignored.
- [x] [data-layer] It still installs the driver in a repo where `.pr-body.md` is tracked.
- [x] [data-layer] A regression test covers both cases and fails before the fix.
- [x] [data-layer] Full `tests/*.test.sh` suite passes.

## Out of scope — and why

**Migrating this repo to the untracked-body model.** otta-build/dev untracked `.pr-body.md` in its #78; this repo still tracks its own. That inconsistency is what hid this bug, and issue #180 flagged it as "worth deciding separately". It is genuinely separate: `merge=ours` is a documented, tested feature backing the tracked model — `README.md:165`, `commands/setup.md:336` and `:475`, `tests/merge-ours-prbody.test.sh`, CHANGELOG #96. Switching the plugin's default would obsolete all of that **for every plugin user**, not just this repo. That is a product decision, not a cleanup.

This fix is deliberately model-agnostic: it makes both models correct, so the decision can be made later without pressure.
